# 내가 Claude Code를 쓰는 방식

비개발자(technical PM)인 내가 Claude Code 하나로 사무 업무 전체를 자동화하면서 몇 달간 다듬은 **작업 방식과 설정의 뼈대**다.
실제 업무 데이터는 하나도 없고, 일하는 법(규칙·스킬·훅·기억 구조)만 담았다. 그대로 복사해서 자기 일에 맞게 고쳐 쓰면 된다.

---

## 1. 핵심 철학 5줄

1. **Claude는 직원 1명이고, 나는 결정권자다.** 방법·기술·구조는 Claude가 정하고 사후 보고한다. 나는 돈·삭제·발송처럼 되돌릴 수 없는 것과 취향 문제만 결정한다.
2. **「계속할까요?」 금지.** 목표를 줬으면 끝까지 간다. 보고는 「다음은 X 하겠습니다」로 끝낸다.
3. **토큰은 아끼지 않는다. 대신 자동으로 읽히는 파일은 가볍게.** 깊은 조사·병렬 서브에이전트에는 아낌없이 쓰고, 매 턴 자동 로드되는 `CLAUDE.md`·`MEMORY.md`는 작게 유지한다.
4. **추측 금지, 실측 단정.** 「아마 이 파일일 것」이 아니라 열어서 확인한 뒤에만 단정한다. 「없다」는 전부 뒤진 뒤에만 말한다.
5. **규칙은 말로 두지 말고 훅으로 강제한다.** 몇 번 어기는 규칙은 hook(훅, Claude가 행동할 때마다 자동으로 도는 검사 스크립트)으로 만든다.

---

## 2. 폴더 구조

```
CLAUDE.md                 ← 헌법. 매 세션 자동 로드. 「일하는 법」만 (짧게)
.claude/
  settings.json           ← 훅 배선
  hooks/                  ← 자동 검사 스크립트 (한국어 강제, 위험 명령 차단 등)
  skills/                 ← 이름으로 부르는 작업 모드 (boost, svt, pilotmax, mission, journal)
memory/
  MEMORY.md               ← 행동·안전 규칙 색인. 한 줄 = 규칙 하나 + 파일 링크
  <규칙>.md               ← 규칙 하나당 파일 하나 (왜 생겼나 + 어떻게 적용하나)
  BACKLOG.md              ← 할 일 목록. 「할일」이라고 부를 때만 읽음
  JOURNAL.md              ← 작업 역사. 「지난 작업」이라고 부를 때만 읽음
  _inbox/                 ← 세션(터미널 창)마다 남기는 작업로그 → 나중에 JOURNAL로 합침
missions/                 ← 며칠 걸리는 큰 작업마다 컨트롤 파일 1개
```

**원칙: 자동으로 읽히는 건 `CLAUDE.md` + `MEMORY.md` 두 개뿐이다.** 역사·백로그·미션은 명령할 때만 읽는다.
처음엔 세션마다 역사·현황을 다 읽게 했는데, 매 세션 6만 토큰이 날아가고 오히려 정확도가 떨어졌다.

---

## 3. 하루 흐름

| 상황 | 내가 하는 말 | Claude가 하는 것 |
|---|---|---|
| 일반 작업 | 그냥 시킨다 | 바로 그 일만 한다 (현황 브리핑 X) |
| 꼭 정확해야 함 | `boost` | 병렬 전수 조사 + 교차검증 |
| 설계가 필요함 | `svt` | 진짜 요구사항 규명 → 추천안 1개 → 위험 사전 점검 |
| 맡기고 자리 비움 | `pilotmax` | 끝까지 자율 진행. 결과 내기 전에 「이게 최선인가」를 스스로 두 번 심사 |
| 며칠짜리 큰 일 | `미션 시작: <목표>` | 미션 파일 1개에 분할·진행 위치·결정 이유를 적고, 다음 세션은 그 파일만 읽고 이어감 |
| 규칙을 알려줌 | `기억해둬: ...` | 훅이 감지 → 반드시 파일에 기록 (말로만 답하고 끝내기 방지) |
| 할 일 확인 | `할일` | `BACKLOG.md`만 읽음 |
| 세션 정리 | `정리해줘` | `_inbox` 작업로그를 `JOURNAL.md`에 합침 |
| 하루 끝 | `커밋` | 범위를 한정해 git add → commit → push |

## 4. 기억 시스템 (가장 중요)

Claude Code는 세션이 끝나면 다 잊는다. 그래서 **기억을 파일로** 만든다.

- **규칙 하나 = 파일 하나.** 형식은 `memory/` 예시 참고. 꼭 넣을 것:
  - **Why**: 이 규칙이 왜 생겼나 (실제로 사고 난 일). 이게 있어야 Claude가 비슷한 다른 상황에도 응용한다.
  - **How to apply**: 구체적으로 무엇을 하나.
- **`MEMORY.md`는 색인만.** 한 줄에 규칙 요지 + 링크. 내용을 여기 쓰면 금방 비대해진다. 🔴 표시는 「절대」, 무표시는 「기본(이유 있으면 벗어나도 됨)」.
- **교정받으면 바로 기록.** 내가 「이렇게 하지 마」라고 하면 그 턴에 규칙 파일을 만들거나 고친다.
- **주기적으로 정리.** 월 1회쯤 중복·모순·낡은 규칙을 합친다. 규칙은 계속 쌓이는 구조고 「완성본」은 없다.

---

## 5. 병렬 서브에이전트

Claude Code의 Agent 도구로 서브에이전트(하위 Claude)를 **여러 개 동시에** 띄울 수 있다.

- 조사·전수 탐색·여러 관점 리뷰는 **거의 항상 병렬**로 시킨다. 예: 「이 레포에 개인정보 있나」 → 고객 / 직원 / 회사기밀 3갈래로 동시에.
- 목적은 속도보다 **깊이**다. 같은 일을 순차로 하면 1.3배 느릴 뿐이지만, 병렬로 하면 서브마다 한 조각에만 집중해서 놓치는 게 확 준다.
- 큰 출력(긴 로그·파일 통독)은 서브에게 보내고 요약만 받는다. 메인 세션 컨텍스트가 20만 토큰을 넘으면 실수가 늘기 때문이다.

---

## 6. 훅 (규칙을 강제하는 장치)

`.claude/hooks/`에 예시가 있고, `.claude/settings.json`에 배선돼 있다.

| 훅 | 언제 | 하는 일 |
|---|---|---|
| `korean_reply_gate.py` | 답변 끝날 때 (Stop) | 최종 답변이 영어면 되돌려서 한국어로 다시 쓰게 함 |
| `memory_keyword_reminder.py` | 내가 말할 때 (UserPromptSubmit) | 「기억해둬·적어둬」가 있으면 「파일에 꼭 기록하라」를 주입 |
| `context_watch.py` | 내가 말할 때 | 세션 컨텍스트가 30만 토큰을 넘으면 경고 |
| `danger_gate.py` | 명령 실행 직전 (PreToolUse) | 위험 명령(대량 삭제·강제 push·메일 발송 등)을 차단. 내가 「승인」이라고 한 직후에만 통과 |
| `_frames.py` | (공용) | 서브에이전트 알림 같은 시스템 메시지를 「내 말」로 착각하지 않게 걸러냄 |

**교훈: 훅은 「등록 + 실제 발동 확인」까지가 설치다.** 파일만 만들고 settings에 배선을 안 해서 몇 주 동안 헛돈 적이 있다.

---

## 7. 안전선 (이것만은 꼭)

- **돈·발송·삭제·비가역 작업은 무조건 사람 확인.** 자율 모드(pilotmax)여도 멈춘다.
- **보내기 직전 대상 건수를 의도와 대조.** 「1명에게」였는데 매칭이 3건이면 멈춘다.
- **비밀(토큰·비밀번호·키)은 레포 밖 폴더에.** `.gitignore`만 믿지 말고 처음부터 레포 안에 두지 않는다.
- **🔴 실제 업무 데이터가 든 레포는 남에게 공유하지 않는다.** git은 지운 파일도 이력에 남긴다. 공유하려면 이 레포처럼 **이력 없는 새 레포에 뼈대만** 옮긴다.

---

## 8. 시작하는 법

1. 이 레포를 받아 자기 작업 폴더에 둔다.
2. `CLAUDE.md`를 읽고 자기 상황에 맞게 고친다 (특히 「질문 허용」·「금지선」).
3. `memory/` 폴더 위치를 정한다. Claude Code 기본 자동 메모리는 `~/.claude/projects/<폴더명>/memory/`다. 그 폴더에 `MEMORY.md`를 두면 매 세션 자동 로드된다.
4. 훅은 Python 3이 필요하다. `.claude/settings.json`의 경로를 확인한다.
5. 처음 2주는 교정할 때마다 「기억해둬」를 붙인다. 이게 쌓여서 내 Claude가 된다.
